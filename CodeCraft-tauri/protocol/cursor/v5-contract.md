# Cursor 独立交互实施与验收 v5

2026-09-23，用户明确批准修订 v4：使用公开 Hooks/MCP 实现 CodeCraft 独立交互，将 Cursor 原生双端同步移出本版验收。v4 和既有失败证据原样保留，不将旧 P0 失败改记为通过。

## 本版交付约定

1. 工具审批：普通工具只在 `preToolUse` 等待；MCP 只在具有服务器信息的 `beforeMCPExecution` 等待，不向任何工具注入参数。Hook 通过自身进程和本次随机事件 ID 领取唯一决定。使用既有手动、风险、自动策略；问题和计划始终人工决定。Hook 超时、离线和故障按 D3-B 返回事件合法放行，界面明确区分决定记录、写出和未确认的执行结果。允许决定不覆盖 Cursor、沙箱或其他 Hook 的权限。
2. 自有 MCP：用户级 stdio 服务使用真实 CodeCraft 辅助进程身份和 Cursor 祖先核验。服务器不信任工具参数中的会话、角色或票据。`codecraft_list_projects` 只列出通过桌面 Hook 安装登记的项目；`codecraft_start_workflow` 创建随机独立工作流 ID，绑定当前 MCP 连接及用户已启用的目标项目。目标项目是本次独立工作流的审阅上下文，不冒充 Cursor 当前工作区或原生对话身份。
3. 问答/计划：`codecraft_ask_user`、`codecraft_review_plan` 接收独立 workflowId 和严格业务 schema。新请求返回 pending；`codecraft_get_result` 领取人工结果，`codecraft_cancel_request` 取消本工作流请求。短调用不依赖未验证的长时 MCP 等待预算。相同业务 ID/相同内容只返回原状态，改参冲突；新 ID 重新人工审阅；计划版本显式比较。结果只领取一次，stdout 不确定不自动重发，重启后旧请求只读。连接退出取消其未完成请求，无法取得原生对话取消信号时按五分钟人工截止结束，不猜原生终态。
4. 计划结果仅约束本次独立审阅。规则指导代理先等待决定；不宣称阻止未关联的 Shell、其他 MCP、Cursor Build 或其他原生工具。原生对话与独立工作流分开展示，绝不按名称、摘要、最近会话或到达顺序合并。
5. 桌面/LAN 共用 permission/question/plan 后端提交、版本校验和结果状态。题目 ID、选择、自由文本、跳过、计划完整正文/任务/阶段、修订反馈和取消均可操作；LAN 沿用认证与审批权限。待提交请求不被自动清理或隐藏。
6. 安装/修复/卸载统一使用现有桌面设置 → Hook 的 Cursor 入口，不再提供单独的配置与诊断面板。安装时登记 Cursor 本机保存的当前窗口项目并修复已启用项目的规则；历史工作区、远程目录和明确停用的项目不自动启用。会话列表不添加来源设置，保留现有 Trae 约束。项目启用以持久化注册和 Windows 文件身份为准；规则只是引导，不能作为后端授权。外部文件写入保留 `.bak`，第三方内容或冲突不覆盖。

## 验收

- 生产 EXE 的 Hook/MCP stdio、文件握手、后端状态与共享 UI 均接通；正式 Release 构建与隔离端到端检查通过。
- 验证两端抢答、版本替换、重复/改参、跨连接工作流、停用项目、取消、过期、stdout 未知、断连和重启。前端校验表单、只读权限和旧快照；桌面/LAN 真实视图检查。
- Cursor 实机证据与合成协议检查分别记录。公开接口的实机覆盖按具体客户端版本/事件说明，未实测的模式不宣称通过旧 P0。
- `nativeShared` 始终 false；不修改 Cursor 程序、伪装内置扩展、模拟原生 ACK、禁用原生权限，或以独立交互抵充原生同步。

## 对 v4 的明确替代

本版不使用 v4 §3 候选票据双事件绑定，不要求自有工作流绑定原生 conversation/generation，不执行 v4 §6 的跨原生工具计划门禁。v4 P0-02—07 中依赖这条绑定的验收以及 P0-09—11/V27—34 原生同步验收不属于 v5。保留 schema、版本、幂等、唯一交付、项目身份、故障语义、安装事务、历史和布局约束中适用的部分。v4 的既有核心与证据继续保留供未来有正式接口时使用。
