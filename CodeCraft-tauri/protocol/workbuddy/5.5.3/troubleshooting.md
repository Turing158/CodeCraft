# 排障与回滚

## 常见状态

| 现象 | 处理 |
| --- | --- |
| 已安装 · 等待加载 | 文件和启用配置已写入，已安装卡片及会话入口立即显示；启动或重启 WorkBuddy 后发起一次会话，再到 Hook 设置中刷新 |
| 已禁用 | 文件仍属已安装；在 WorkBuddy 中重新启用 CodeCraft 插件后刷新，不会在启动 CodeCraft 时强制重新启用 |
| 已登记，尚未收到事件 | installed_plugins.json 只证明登记；收到本次本地桥的实际 Hook 事件后才确认加载 |
| 等待会话 | 本次本地桥已收到过 Hook 事件，但当前没有连接中的会话；在 WorkBuddy 中发起或继续会话 |
| 修改 / 冲突 | owner/hash/marketplace 不一致；停止自动修复，对照 .bak，不删除其他插件 |
| 连接异常 / 本地桥未就绪 | 保留已安装状态和会话入口，悬停顶部状态可查看具体错误；到 Hook 设置中刷新，仍未恢复时重启 CodeCraft |
| 身份不完整，仅隔离观察 | PID/目录/会话未完整关联，不是可提交会话；不要伪造 PID/hash |
| 无批准按钮 | 预期行为，见 P0 决策；修改 capability 不能开启 |
| 工具失败却无 PostToolUseFailure | 2.137.1 可在 PostToolUse.tool_response.is_error 上报失败，当前两者均处理 |
| 问题仍在原生界面 | 原生授权可能先于 PreToolUse；请在 WorkBuddy 处理，CodeCraft 不注入答案 |
| 计划正文不可用 | 不读取 Hook 任意路径，不批准未知正文；请在原生界面审阅 |

桌面详情“会话身份与只读诊断”显示原生/集成 ID、版本、目录摘要、插件/进程实例及重复/迟到/隔离/资源丢弃计数。身份信息不是授权证明；计数在内存中，重启归零，不是完整持久审计。

## 保留与容量

- HTTP/stdin 最多 256 KiB，安装配置读取最多 1 MiB，插件桥配置最多 16 KiB。
- 字符串最多 4096 字符，超限带长度/hash 摘要；字段数、深度、数组亦有限制。脱敏是尽力规则，不应主动把敏感原始命令交给工具。
- 最多 256 会话、512 全局交互、每会话 64 交互；每会话 100 活动/40 输出，去重缓存 4096。全活跃达上限时拒收新会话。
- 应用数据根/CodeCraft/workbuddy-hook/inbox 的 json/consumed/invalid/tmp 各最多 512 个、32 MiB、24 小时。写入及约每 30 秒清理生成观察记录，安装备份不自动清理。
- 桥 nonce 最多 2048、保留 10 分钟；满时拒绝新请求，不驱逐活跃防重放记录。令牌有效 10 分钟、约 5 分钟轮换；桥重启产生新实例与令牌。
- 观察请求 30 分钟到期，进程死亡约每 30 秒检查，不能称为即时撤销。没有决定 outbox 或 pending 同步提交器，没有已提交决定可重试。
- 生产不签发 WorkBuddy LAN capability；验证器绑定 LAN 登录与具体集成会话，测试 TTL 为 10 分钟。LAN 写开关不越过协议门禁；退出/轮换会撤销服务器会话。没有远程特性关闭服务。

.workbuddy-verification 是开发采集目录，不受产品 24 小时清理管理。确认已导出证据后，可手动清理某个精确的测试子目录；原始大段提示不应上传。

## 卸载与恢复

1. Hook 管理取消 WorkBuddy 自动安装，再执行卸载；重启 WorkBuddy，避免使用缓存插件。
2. 卸载只移除 owner/hash 有效的三个插件资源、安装清单、CodeCraft marketplace 与对应 settings 条目；其他插件、Hook、MCP、权限、未知字段及备份保留。
3. 修改/删除前建立不覆盖的 .bak；已有首份备份时用内容 hash 后缀保存另一版。JSONC 注释不会重新序列化，但原始字节在备份里。
4. hash/owner/备份冲突时卸载停止，不强删。人工恢复只合并相关条目，不用旧的完整 settings 覆盖后来用户修改。
5. 事务失败尝试恢复本次已改文件；若有并发修改则不覆盖它，返回冲突并保留备份，需人工合并。

本轮安装/卸载验证均在项目内临时配置，未修改用户真实 WorkBuddy 配置。
